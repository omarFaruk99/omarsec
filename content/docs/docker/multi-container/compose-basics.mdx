# Compose Basics

<Callout type="info">
This page introduces the tool, and one simple example, before the next page grows it into a full stack.
</Callout>

## What Docker Compose Is

Docker Compose lets you describe every container your project needs — images, ports, volumes, environment variables, networks — in a single YAML file. One command starts everything; one command stops everything.

<Callout type="default">
Recall Container Networking from the last section: you manually ran `docker network create`, then attached two containers to it with `--network`. Compose does exactly that for you, automatically, for every service in the file.
</Callout>

## `docker compose`, Not `docker-compose`

You may see two different commands in older tutorials:

- `docker-compose` (with a hyphen) — the original, standalone tool. It still works on many machines, but it is the legacy version.
- `docker compose` (a space, as a subcommand of `docker` itself) — **Compose v2**, built directly into the Docker CLI. This is the current version, and the one this guide uses.

Check which you have:

```bash filename="Terminal"
docker compose version
```

If that fails, your Docker installation may only have the older standalone tool. Docker Desktop includes Compose v2 by default.

## Your First `compose.yaml`

Create a file named `compose.yaml` in your Next.js project's root folder — the same folder as your `Dockerfile`:

```yaml filename="compose.yaml"
services:
  web:
    build: .
    ports:
      - "3000:3000"
```

- `services:` — the list of containers this project needs. There is one so far: `web`.
- `build: .` — instead of a pre-built image, build one from the Dockerfile in this folder, exactly like `docker build .` from Building Images.
- `ports:` — the same idea as `-p 3000:3000` on the command line.

## Running It

<Steps>

### Start it

```bash filename="Terminal"
docker compose up
```

This builds the image (if needed) and starts the container, with logs printed straight to your terminal.

### Start it in the background

```bash filename="Terminal"
docker compose up -d
```

`-d` runs detached, exactly like `docker run -d` did in Foundation.

### See what is running

```bash filename="Terminal"
docker compose ps
```

### View logs

```bash filename="Terminal"
docker compose logs -f web
```

### Stop everything

```bash filename="Terminal"
docker compose down
```

This stops and removes the containers Compose created — but not the image, and not any named volumes, unless you add `-v`.

</Steps>

<Callout type="warning">
`docker compose down -v` also deletes named volumes. Do not add `-v` if you have real data you want to keep — the next pages will make this distinction matter.
</Callout>
