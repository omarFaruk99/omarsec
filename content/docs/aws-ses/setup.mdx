# Setup

<Callout type="info">
পুরো সেটআপ প্রসেসটা এই একটা পেজে ক্রম অনুযায়ী দেখানো হয়েছে। উপর থেকে নিচে করুন — প্রতিটা অংশ আগেরটার উপর নির্ভর করে (যেমন domain verify না হলে production access request করা যাবে না)।
</Callout>

## AWS Account ও Test Mail

<Steps>

### AWS Account খোলা

aws.amazon.com → **Create an AWS Account** → ইমেইল, পাসওয়ার্ড, কার্ড তথ্য দিয়ে সাইনআপ সম্পূর্ণ করুন।

### Region বাছা

AWS Console → উপরে ডানদিকে কোণায় region ড্রপডাউন (যেমন লেখা থাকবে "N. Virginia" বা অন্য কিছু) → ক্লিক করে **Asia Pacific (Singapore) ap-southeast-1** বাছুন।

<Callout type="warning">
যা বাছবেন এই region-ই মনে রাখবেন — বাকি সব ধাপ এই একই region-এ করতে হবে।
</Callout>

### SES কনসোলে যাওয়া

উপরে সার্চ বক্সে লিখুন `SES` → **Amazon Simple Email Service** ক্লিক করুন।

### Test Email ভেরিফাই করা (sender + receiver)

SES কনসোল → **Configuration → Identities** → **Create identity** বাটন → Identity type = **Email address** → ইমেইল লিখুন → **Create identity**।

- ওই ইমেইলে AWS-এর confirm লিংক আসবে → ক্লিক করুন।
- এই কাজ দুইবার করুন — একবার sender ইমেইল দিয়ে, একবার receiver ইমেইল দিয়ে (দুইটা আলাদা ইমেইল এড্রেস)।

### Console থেকে Test Mail পাঠানো

Identities লিস্ট → sender ইমেইলে ক্লিক করুন → উপরে ডানে **Send test email** বাটন → To বক্সে receiver ইমেইল দিন → **Send test email**।

<Callout type="info">
মেইল পেলেও এই ধাপে Spam folder-এ যাওয়া স্বাভাবিক — কারণ এখনো domain ভেরিফাই করা হয়নি (SPF/DKIM নেই)। নিচের Domain Verification অংশ শেষ হলে এটা ঠিক হয়ে যাবে।
</Callout>

</Steps>

## Domain Verification

ইতিমধ্যে ডোমেইন থাকলে এই sub-section-এর প্রথম ধাপ বাদ দিয়ে "Cloudflare-এ Add Site" থেকে শুরু করুন।

namecheap.com → সার্চে চাওয়া domain লিখুন → কার্টে নিয়ে checkout করুন।

<Steps>

### Cloudflare-এ Add Site

dash.cloudflare.com → **Add a site** → domain লিখুন → Free plan বাছুন → Cloudflare দুইটা nameserver দেখাবে।

### Namecheap-এ Nameserver বদলানো

Namecheap → Domain List → domain-এর পাশে **Manage** → **Nameservers** → **Custom DNS** বাছুন → Cloudflare-এর দেওয়া দুইটা nameserver বসান → Save।

</Steps>

<Callout type="info">
নতুন nameserver active হতে কয়েক ঘণ্টা লাগতে পারে।
</Callout>

### SES-এ Domain ভেরিফাই করা

**কেন এই ধাপ?** Gmail/Yahoo জানতে চায় — এই ডোমেইনের মালিক কি সত্যিই আপনি? এই ধাপ সেটার প্রমাণ দেয়।

মূল ডোমেইন সরাসরি না দিয়ে একটা sub-domain দেওয়া ভালো (যেমন `mail.yourcompany.com`), যাতে bulk mail-এ সমস্যা হলে মূল ওয়েবসাইট/ইমেইলের সুনাম (reputation) নষ্ট না হয়।

SES → **Identities** → **Create identity** → Identity type = **Domain** → domain/sub-domain লিখুন।

নিচে আরও কিছু অপশন দেখাবে:

| অপশন | কী করবেন |
|---|---|
| **DKIM signatures** | চালু/on রাখুন — মেইল প্রমাণ করার আসল জিনিস এটাই |
| **DKIM signing key length** | Default রাখুন (RSA 2048-bit) |
| **Publish DNS records to Route 53** | বন্ধ/off রাখুন — এটা শুধু DNS Route53-এ থাকলে লাগে, Cloudflare ব্যবহার করলে দরকার নেই |

আরও নিচে এই ৩টা checkbox দেখাবে — তিনটাই খালি/unchecked রাখুন (এখন দরকার নেই):

| Checkbox | কেন skip |
|---|---|
| **Assign a default configuration set** | event tracking (open/click/bounce)-এর advanced ফিচার, পরে আলাদাভাবে যোগ করা যায় |
| **Assign to a tenant** | multi-tenant/enterprise setup-এর জন্য, একজনের জন্য দরকার নেই |
| **Use a custom MAIL FROM domain** | DMARC আরও কড়া করে, কিন্তু DKIM already on থাকায় এটা ছাড়াই DMARC pass করবে |

শেষে **Create identity** ক্লিক করুন।

Identity তৈরি হওয়ার পর, ওই identity-এর পেজে **Authentication** ট্যাবে দুইটা জায়গায় "Publish DNS records" দেখবেন — একটা **DKIM** সেকশনে, একটা **DMARC** সেকশনে।

<Callout type="warning">
দুই জায়গাতেই ক্লিক করুন — একটা বাছতে হবে না, দুটোই লাগে। ক্লিক করলে রেকর্ডের Type/Name/Value দেখাবে — Route53 use না করায় এটা কোথাও নিজে থেকে বসবে না, শুধু কপি করার জন্য দেখাবে।
</Callout>

### DKIM/DMARC রেকর্ড Cloudflare-এ বসানো

Cloudflare → আপনার domain → **DNS** সেকশন → **Records** → **Add record** → নিচেরগুলো এক এক করে বসান।

**DKIM (৩টা CNAME)** — উপরের DKIM সেকশনে যা Name ও Value দেখিয়েছে, সেগুলো হুবহু কপি করে বসান।

**DMARC (১টা TXT)** — উপরের DMARC সেকশনে যা দেখিয়েছে (সাধারণত default `p=none` দিয়ে), সেটাও হুবহু কপি করে বসান।

`p=none` মানে শুরুতে শুধু রিপোর্ট পাঠাবে, মেইল ব্লক করবে না — কয়েক সপ্তাহ পর্যবেক্ষণ করে পরে `p=quarantine` বা `p=reject`-এ কড়া করা যায়।

**SPF (ঐচ্ছিক, SES নিজে থেকে দেখায় না):** যেহেতু "Use a custom MAIL FROM domain" আমরা skip করেছি, SES ডিফল্টভাবে নিজের `amazonses.com` address দিয়ে পাঠায় — সেখানে SPF আগে থেকেই ঠিক করা আছে। তাই DKIM + DMARC-ই যথেষ্ট, SPF আলাদা করে বসানো এখন বাধ্যতামূলক না।

<Callout type="warning">
প্রতিটা রেকর্ড বসানোর সময় proxy status **DNS only (grey cloud)** রাখুন, orange cloud না — মেইল রেকর্ডে Cloudflare-এর প্রক্সি কাজ করে না।
</Callout>

### Domain Verified হওয়ার অপেক্ষা

SES → Identities → domain নামের পাশে status চেক করুন।

- Status **Pending** থেকে **Verified** হতে সাধারণত ৫ মিনিট থেকে কয়েক ঘণ্টা লাগে, তবে AWS বলে সর্বোচ্চ ৭২ ঘণ্টা পর্যন্ত লাগতে পারে।
- DKIM status আলাদাভাবে **Successful** দেখাতে হবে — শুধু domain verified হলেই চলবে না, DKIM-ও verified হতে হবে।
- এই সময়টায় SES-এর **Get set up** পেজে "Request production access" বাটন disabled (ধূসর) থাকবে — এটা স্বাভাবিক, verify হলেই চালু হবে।

## Sending Credentials

<Callout type="info">
দুইটা রাস্তা আছে — API (Access Key) অথবা SMTP। যেকোনো একটা করলেই চলে, দুটোই লাগে না।
</Callout>

**Access Key বানানো (API দিয়ে পাঠাতে চাইলে):**

<Steps>

### IAM User বানানো

সার্চ বক্সে লিখুন `IAM` → **IAM** কনসোল → বামের সাইডবারে **Access Management → IAM users** ক্লিক → **Create user** → নাম দিন (যেমন `ses-sender`) → Next → **Attach policies directly** → সার্চে `AmazonSESFullAccess` লিখে টিক দিন → Create user।

### Access Key তৈরি

IAM users লিস্ট → `ses-sender` ক্লিক → **Security credentials** ট্যাব → **Create access key** → Use case = **Application running outside AWS** → Create access key।

</Steps>

<Callout type="warning">
`Access Key ID` ও `Secret Access Key` দেখাবে — একবারই দেখাবে, সাথে সাথে ডাউনলোড/সেভ করুন।
</Callout>

### SMTP Credential বানানো (SMTP দিয়ে পাঠাতে চাইলে, ঐচ্ছিক)

<Callout type="info">
Access Key ইতিমধ্যে করে থাকলে এই sub-section স্কিপ করুন। SMTP পুরনো mail library-এর সাথে সহজে কাজ করে।
</Callout>

SES কনসোল → বামের সাইডবারে **SMTP settings** → এখানে দুইটা অপশন দেখাবে:

| অপশন | কী করবেন |
|---|---|
| **Mail Manager SMTP** (default/Recommended) | বাছবেন না — এটায় extra "Mail Manager processing charges" আছে |
| **IAM SMTP credentials** | এটা বাছুন — ফ্রি, সাধারণ ব্যবহারের জন্য যথেষ্ট |

**IAM SMTP credentials** বেছে → **Create SMTP credentials** → একটা **"Create user for SMTP"** পেজ খুলবে:

- **User name** — default রাখা যায় (যেমন `ses-smtp-user.20260820-200820`)
- **Permissions** — AWS নিজে থেকে একটা group বানাবে (`AWSSESSendingGroupDoNotRename`), যাতে শুধু `ses:SendRawEmail` permission থাকে — এটা Access Key-এর `AmazonSESFullAccess`-এর চেয়েও নিরাপদ (শুধু মেইল পাঠানোর অনুমতি, আর কিছু না)
- **Tags** — খালি রাখুন (ঐচ্ছিক)

শেষে **Create user** ক্লিক করুন। এরপর **"Retrieve SMTP credentials"** পেজে দেখাবে:

- **IAM user name** — যা উপরে দিয়েছিলেন
- **SMTP user name** — এটা IAM user name থেকে আলাদা, Access Key-এর মতো দেখতে একটা কোড (যেমন `AKIAV27H45JYYYORBG6C`)
- **SMTP password** — লুকানো থাকে, **Show** ক্লিক করলে দেখা যায়

<Callout type="warning">
এই পেজেই একবারই SMTP password দেখাবে — পরে আর ফিরে দেখা যাবে না। **Download .csv file** বাটনে ক্লিক করে সেভ করে রাখুন।
</Callout>

<Callout type="info">
নতুন console-এ SMTP endpoint/port আলাদাভাবে আর দেখায় না — এটা region অনুযায়ী ফিক্সড:
- **Endpoint:** `email-smtp.<region>.amazonaws.com` (যেমন আপনার region `ap-southeast-1` হলে `email-smtp.ap-southeast-1.amazonaws.com`)
- **Port:** `587` (recommended, STARTTLS দিয়ে) — বিকল্প হিসেবে `465` (TLS wrapper) ব্যবহার করা যায়, `25` এড়িয়ে চলুন
</Callout>

## Production Access

<Steps>

### Production Access রিকোয়েস্ট করা

SES → বামের সাইডবারে **Get set up** → "Request production access" কার্ডে **Request production access** বাটন ক্লিক করুন (domain verify শেষ না হলে এই বাটন disabled থাকবে) → ফর্মে জানতে চাইবে:

- মেইল কী ধরনের (Marketing/Transactional)
- লিস্ট কীভাবে বানানো (মানুষ কীভাবে subscribe করেছে)
- Unsubscribe আছে কিনা
- Bounce/complaint কীভাবে সামলাবেন

ফর্ম পূরণ করে **Submit for review**।

<Callout type="info">
সাধারণত ২৪–৪৮ ঘণ্টায় সিদ্ধান্ত আসে (ইমেইলে)।
</Callout>

### Production Approve হওয়া চেক করা

SES → Account dashboard → **Sending limits** সেকশনে "Sandbox" এর বদলে দেখাবে **Production access granted**, সাথে দৈনিক sending quota।

### Developer-কে হ্যান্ডওভার

নিচেরগুলো নিরাপদে (পাসওয়ার্ড ম্যানেজার/এনক্রিপ্টেড শেয়ার — চ্যাটে না) দিন:

- AWS Region (যেমন `ap-southeast-1`)
- Access Key ID + Secret Access Key (API ব্যবহার করলে)
- SMTP endpoint + username + password (SMTP ব্যবহার করলে)
- ভেরিফাই করা sender domain/email (যেমন `no-reply@mail.yourcompany.com`)
- Production access পাওয়া গেছে কনফার্ম
- Cloudflare DNS এডিট এক্সেস (পরে নতুন রেকর্ড লাগতে পারে)

</Steps>

## CyberSec Note

<Callout type="warning">
এই পুরো সেটআপের কেন্দ্রে আছে **spoofing/phishing prevention**: DKIM/SPF/DMARC প্রমাণ করে মেইলটা আসল domain থেকেই এসেছে, আর AWS ইচ্ছা করেই নতুন account-কে Sandbox-এ আটকে রাখে যাতে কেউ SES ব্যবহার করে spam/phishing campaign চালাতে না পারে। Access Key/SMTP credential leak হলে যে কেউ আপনার verified domain থেকে মেইল পাঠাতে পারবে — তাই এটা কখনো কোডে hardcode বা Git repository-তে commit করবেন না, `.env` + `.gitignore` ব্যবহার করুন।
</Callout>
