# Git & GitHub — Cheatsheet

<Callout type="info">
সব important commands এক জায়গায়। Bookmark করো, print করো, দেওয়ালে লাগাও।

এটা reference — শেখার জায়গা না। কোনো কমান্ড কেন কাজ করে সেটা জানতে সংশ্লিষ্ট page-এ যাও।
</Callout>

## Initial Setup

গিট ইনস্টল করার পর প্রথমবার যে কনফিগারেশনগুলো করতে হয়।


```bash filename="Terminal"
git --version                              # Git installed কিনা check করো
git config --global user.name "Your Name"  # তোমার নাম set করো
git config --global user.email "you@example.com"  # তোমার email set করো
git config --global init.defaultBranch main        # Default branch নাম
git config --list                          # সব config দেখো
```

## Project Start

নতুন রিপোজিটরি তৈরি বা গিটহাব থেকে ক্লোন করার কমান্ডসমূহ।


```bash filename="Terminal"
git init                                   # নতুন repo শুরু করো
git clone git@github.com:user/repo.git     # GitHub থেকে clone করো
git remote -v                              # Remote connections দেখো
git remote add origin git@github.com:user/repo.git  # Remote add করো
git remote set-url origin git@github.com:user/repo.git  # Remote URL change করো
```

## Daily Workflow

প্রতিদিনের কাজে সবচেয়ে বেশি ব্যবহৃত গিট কমান্ডগুলো।


```bash filename="Terminal"
git status                                 # কী কী changed দেখো
git add filename.txt                       # Specific file stage করো
git add .                                  # সব changes stage করো
git restore --staged filename.txt          # Stage থেকে বাদ দাও
git commit -m "Your message here"          # Commit করো
git push                                   # GitHub-এ upload করো
git push -u origin main                    # প্রথমবার push (branch set করে)
git pull                                   # GitHub থেকে latest নামাও
git fetch origin                           # Download করো, apply করো না
```

## Branching

নতুন ব্রাঞ্চ তৈরি, ডিলিট এবং সুইচ করার প্রোফেশনাল কমান্ডসমূহ।


```bash filename="Terminal"
git branch                                 # Local branches দেখো
git branch -a                              # সব branches দেখো (remote সহ)
git switch branch-name                     # Branch-এ যাও
git switch -c feature/new-feature          # নতুন branch বানাও এবং যাও
git branch -d branch-name                  # Branch delete করো (merged)
git branch -D branch-name                  # Branch force delete করো
git push origin --delete branch-name       # Remote branch delete করো
git fetch --prune                          # Deleted remote branches clean করো
```

## Merging

বিভিন্ন ব্রাঞ্চের কোড এক জায়গায় করার প্রয়োজনীয় কমান্ডগুলো।


```bash filename="Terminal"
git merge branch-name                      # Branch merge করো
git merge origin/main                      # Remote main merge করো
git merge --abort                          # Merge cancel করো (conflict-এ)
```

## Stash

অর্ধেক করা কাজগুলো সাময়িকভাবে জমা রাখার সহজ কমান্ডসমূহ।


```bash filename="Terminal"
git stash                                  # Current changes সরিয়ে রাখো
git stash -u                               # নতুন (untracked) file-সহ stash করো
git stash push -u -m "half-done filter"    # নাম দিয়ে stash করো
git stash pop                              # ফিরিয়ে আনো, stash থেকে মুছে যাবে
git stash apply stash@{1}                  # ফিরিয়ে আনো, stash-এ থেকে যাবে
git stash list                             # সব stash দেখো
git stash drop                             # Latest stash delete করো
git stash clear                            # সব stash delete করো
```

## View History

তোমার কাজের পূর্ণাঙ্গ ইতিহাস দেখার বিভিন্ন উপায়।


```bash filename="Terminal"
git log                                    # Full commit history
git log --oneline                          # Short history
git log --oneline --graph                  # Branch tree সহ history
git log --author="Name"                    # নির্দিষ্ট কারো commits
git log --since="2 weeks ago"              # নির্দিষ্ট সময়ের commits
git diff                                   # Unstaged changes দেখো
git diff --staged                          # Staged changes দেখো
git show a1b2c3d                           # Specific commit দেখো
```

## Undo Actions

ভুলবশত করা কাজগুলো আগের অবস্থায় ফিরিয়ে নেওয়ার নিয়ম।


<Tabs items={['Commit করার আগে', 'Commit করার পর (push করোনি)', 'Push করার পর']}>
  <Tabs.Tab>
    ```bash filename="Terminal"
    git restore filename.txt                   # File-এর changes undo করো
    git restore --staged filename.txt          # Unstage করো
    git restore --source=HEAD~3 file.js        # ৩ commit আগের version আনো
    git clean -n -d                            # কোন untracked file মুছবে দেখো
    git clean -f -d                            # untracked file মুছে ফেলো
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```bash filename="Terminal"
    git commit --amend -m "New message"        # Last commit message fix করো
    git reset --soft HEAD~3                    # ৩ commit খোলো, কাজ staged থাকবে
    git reset HEAD~1                           # commit খোলো, কাজ unstaged (default)
    git reset --hard HEAD~1                    # commit আর কাজ — সব মুছে দাও
    git reset --hard origin/main               # local branch = remote branch
    git reset --hard main                      # এই branch = main
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```bash filename="Terminal"
    git revert a1b2c3d                         # Specific commit reverse করো (safe)
    git revert -m 1 a1b2c3d                    # Merge commit reverse করো
    ```
  </Tabs.Tab>
</Tabs>

| Mode | Commit | Staging | Working Directory |
| :--- | :--- | :--- | :--- |
| `--soft` | পিছোয় | কাজ এখানে থাকে | অপরিবর্তিত |
| `--mixed` (default) | পিছোয় | খালি | কাজ এখানে থাকে |
| `--hard` | পিছোয় | খালি | কাজ মুছে যায় |

<Callout type="warning">
- `reset --hard` সাবধানে — uncommitted changes permanently মুছে যায়।
- Push করার পর `reset` করবে না — `revert` ব্যবহার করো।
- `reset --hard origin/main` দেওয়ার আগে `git fetch` করো।

পুরো ব্যাখ্যা: [Undo & Recovery](/docs/git-github/undo-and-recovery)
</Callout>

## Recovery

হারিয়ে যাওয়া commit বা branch ফিরিয়ে আনার কমান্ড।

```bash filename="Terminal"
git reflog                                 # HEAD কোথায় কোথায় গিয়েছিল দেখো
git show 1e5a7b8                           # ফেরানোর আগে commit যাচাই করো
git reset --hard 1e5a7b8                   # ওই commit-এ ফিরে যাও
git switch -c recovery 1e5a7b8             # নিরাপদভাবে নতুন branch-এ ফেরাও
git switch -c old-branch 1e5a7b8           # delete করা branch ফিরিয়ে আনো
```

<Callout type="info">
reflog শুধু তোমার মেশিনে থাকে, আর commit না করা কাজ ওখানে নেই।
</Callout>

## Rebase

Branch আপডেট রাখা আর history পরিষ্কার করার কমান্ড।

```bash filename="Terminal"
git fetch origin                           # আগে latest আনো
git rebase origin/main                     # main-এর উপরে branch তুলে আনো
git rebase -i HEAD~5                       # শেষ ৫ commit নিয়ে কাজ করো
git pull --rebase origin main              # merge commit ছাড়া pull

# Conflict এলে (commit লিখবে না)
git add .
git rebase --continue                      # পরের commit-এ এগোও
git rebase --skip                          # এই commit বাদ দাও
git rebase --abort                         # সব বাতিল, আগের অবস্থায় ফেরো

git push --force-with-lease                # rebase-এর পর push
```

Interactive rebase-এর command: `pick`, `reword`, `squash`, `fixup`, `drop`.

<Callout type="warning">
`main`, `develop`, `staging` — shared branch কখনো rebase করবে না। `git push -f` নয়, সবসময় `--force-with-lease`।

পুরো ব্যাখ্যা: [Rebase & History](/docs/git-github/rebase-and-history)
</Callout>

## Cherry-pick & Bisect

নির্দিষ্ট commit কপি করা আর bug কোন commit-এ এসেছে খোঁজা।

```bash filename="Terminal"
git cherry-pick 4a1f9c2                    # ওই commit এই branch-এ কপি করো
git cherry-pick -x 4a1f9c2                 # সাথে উৎস commit লিখে রাখো
git cherry-pick a1b2c3d..9f2c1a4           # একটা range কপি করো
git cherry-pick --continue                 # conflict fix করার পর
git cherry-pick --abort                    # বাতিল করো

git bisect start
git bisect bad                             # এখন ভাঙা
git bisect good v2.3.0                     # এখানে ঠিক ছিল
git bisect run npm test                    # নিজে থেকেই খুঁজে দেবে
git bisect reset                           # কাজ শেষে অবশ্যই
```

## Tags

সফটওয়্যারের নির্দিষ্ট ভার্সন মার্ক করার জন্য ট্যাগ ব্যবহারের নিয়ম।


```bash filename="Terminal"
git tag                                    # সব tags দেখো
git tag -a v1.0.0 -m "First release"      # Annotated tag বানাও
git push origin v1.0.0                     # Tag GitHub-এ push করো
git push origin --tags                     # সব tags push করো
```

## Fork Workflow

অন্যের প্রোজেক্টে কন্ট্রিবিউট করার জন্য ফর্ক সিঙ্ক করার কমান্ড।


```bash filename="Terminal"
# Fork clone করার পর
git remote add upstream git@github.com:original/repo.git

# Fork sync করো
git fetch upstream
git switch main
git merge upstream/main
git push origin main
```

## Hotfix Workflow

লাইভ সাইটের ইমারজেন্সি সমস্যা সমাধানের পূর্ণাঙ্গ গাইড।


```bash filename="Terminal"
# ১. Production ব্রাঞ্চে যাও এবং লেটেস্ট কোড নামাও
git switch main
git pull

# ২. ইমারজেন্সি হটফিক্স ব্রাঞ্চ তৈরি করো
git switch -c hotfix/critical-bug-fix

# [বাগ ফিক্স করো...]

# ৩. ফিক্স সেভ (commit) করো
git add .
git commit -m "Fix critical bug"

# ৪. Main-এ ফিরে ফিক্সটি মার্জ করে লাইভ করো
git switch main
git merge hotfix/critical-bug-fix
git push

# ৫. (Optional) নতুন ভার্সন ট্যাগ করো
git tag -a v1.0.1 -m "Hotfix: critical bug"
git push origin v1.0.1

# ৬. Develop ব্রাঞ্চেও ফিক্সটি সিঙ্ক করো (অত্যন্ত জরুরি)
git switch develop
git merge hotfix/critical-bug-fix
git push

# ৭. কাজ শেষে লোকাল ব্রাঞ্চটি ক্লিনআপ করো
git branch -d hotfix/critical-bug-fix
```

## Commit Guide

পেশাদার এবং অর্থবহ কমিট মেসেজ লেখার একটি সংক্ষিপ্ত ডিরেক্টরি।


### Types
| Type | কখন |
|------|------|
| `feat:` | নতুন feature |
| `fix:` | Bug fix |
| `docs:` | Documentation |
| `style:` | Formatting (code logic change না) |
| `refactor:` | Code restructure |
| `chore:` | Dependency update, config change |

### উদাহরণ
```bash filename="Terminal"
feat: add price filter to product listing
fix: resolve login redirect on Safari
docs: update README with installation steps
chore: update npm dependencies
```

## Naming Guide

ব্রাঞ্চের নাম দেওয়ার প্রফেশনাল স্ট্যান্ডার্ডগুলো একনজরে দেখো।


```
feature/short-description      → নতুন feature
fix/short-description          → Bug fix
hotfix/short-description       → Emergency live fix
docs/short-description         → Documentation
chore/short-description        → Cleanup, update
```

## Panic Fixes

জরুরি মুহূর্তে ভুল ফিক্স করার জন্য কিছু কমন সলিউশন।


<Tabs items={['ভুল branch', '.env push হয়ে গেছে', 'Push rejected', 'Merge conflict', 'আগের commit-এ ফেরা', 'কাজ হারিয়ে ফেলেছি']}>
  <Tabs.Tab>
    "আমি ভুল branch-এ commit করেছি!"
    
    ```bash filename="Terminal"
    git reset HEAD~1                           # Commit undo করো
    git switch correct-branch                  # সঠিক branch-এ যাও
    git add .
    git commit -m "Your message"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    "আমি `.env` file push করে ফেলেছি!"
    
    ```bash filename="Terminal"
    # ১. সবার আগে key rotate করো — AWS, Stripe, database
    #    এটাই একমাত্র আসল সুরক্ষা। commit মুছলেও key ফাঁস হয়ে গেছে।

    # ২. .env কে .gitignore-এ যোগ করো
    echo ".env" >> .gitignore

    # ৩. Git tracking থেকে বাদ দাও
    git rm --cached .env
    git commit -m "chore: remove .env from tracking"
    git push
    ```

    `reset --hard` আর force push দিয়ে secret মোছা যায় না — commit-টা URL দিয়ে এখনো পড়া যায়। কেন, সেটা [Undo & Recovery](/docs/git-github/undo-and-recovery)-তে আছে।
  </Tabs.Tab>
  <Tabs.Tab>
    "Push করতে পারছি না — rejected!"
    
    ```bash filename="Terminal"
    git pull                                   # Latest নামাও আগে
    # conflict হলে fix করো
    git push                                   # আবার push করো
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    "Merge conflict এসেছে!"
    
    ```bash filename="Terminal"
    git status                                 # কোন files conflict-এ দেখো
    # Files খুলে <<<<<<< ======= >>>>>>> manually fix করো
    git add .
    git commit -m "Resolve merge conflict"
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    "পুরো কাজ নষ্ট করে ফেলেছি, আগের commit-এ ফিরতে চাই!"

    Push করোনি — তাহলে সরাসরি ওই commit-এ ফিরে যাও:

    ```bash filename="Terminal"
    git log --oneline                          # কোন commit-এ ফিরবে দেখো
    git reset --hard a1b2c3d                   # ওই অবস্থায় ফিরে যাও
    ```

    Push করে ফেলেছ — তাহলে history পাল্টাবে না, উল্টো commit বানাও:

    ```bash filename="Terminal"
    git revert a1b2c3d                         # ওই commit-এর উল্টো কাজ করো
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    "`reset --hard` করে কয়েক দিনের commit হারিয়ে ফেলেছি!"

    হারায়নি। reflog-এ সব আছে।

    ```bash filename="Terminal"
    git reflog                                 # reset-এর আগের লাইনটা খুঁজো
    git show 1e5a7b8                           # নিশ্চিত হও এটাই ঠিক commit
    git switch -c recovery 1e5a7b8             # নিরাপদে নতুন branch-এ ফেরাও
    ```

    Branch delete করে ফেললেও একইভাবে ফিরিয়ে আনা যায়। শুধু `git commit` না করা কাজ ফেরানো যায় না।
  </Tabs.Tab>
</Tabs>

## Full Workflow

প্রতিদিনের কাজের একটি আদর্শ ফ্লো যা তোমার মুখস্থ রাখা উচিত।


<Steps>
### সকালে
```bash filename="Terminal"
git switch main
git pull
git switch -c feature/your-task
```

### কাজের মাঝে (বারবার)
```bash filename="Terminal"
git add .
git commit -m "Descriptive message"
```

### দিনের শেষে
```bash filename="Terminal"
git push -u origin feature/your-task
```

### কাজ শেষে (PR merge হওয়ার পর)
```bash filename="Terminal"
git switch main
git pull
git branch -d feature/your-task
```
</Steps>


## Real-World Note

<Callout type="warning">
  এই page-এর তিনটা কমান্ড কাজ ফিরিয়ে দেওয়া যায় না এমনভাবে মুছে দিতে পারে। চালানোর আগে থামো।

  - `git reset --hard` — commit না করা কাজ চিরতরে যায়
  - `git clean -f -d` — untracked file চিরতরে যায় (`-n` দিয়ে আগে দেখো)
  - `git push --force` — remote-এ অন্যের কাজ মুছে দিতে পারে (`--force-with-lease` ব্যবহার করো)

  Cheatsheet থেকে কমান্ড copy করার আগে নিশ্চিত হও তুমি জানো এটা কী করে। না জানলে সংশ্লিষ্ট page-টা পড়ে নাও।
</Callout>
